一次研究如何执行

分析师、多空研究员、交易员和风险辩手使用 quick_think_llm 指定的模型。研究经理和组合经理使用 deep_think_llm 指定的模型，分别形成研究计划和最终判断。角色与模型的分配

情绪分析中还有一个可选步骤。启用 Jev 时，它先筛选 StockTwits 和 Reddit 帖子，判断帖子是否与标的相关，并统计作者立场。情绪分析师随后使用 quick 档模型综合新闻和社交资料，撰写报告。Jev 筛选逻辑 · 情绪报告生成逻辑

以输入 600519.SH、选择 market 和 news、指定一个过去的研究日期为例。这个例子只演示调用顺序，未请求行情或生成投资结论。

  1. 入口 CLI 收集输入，或由 Python 调用 propagate。
  2. 准备 Graph 构建初始状态，写入标的、日期、证券身份与持仓上下文。
  3. 并行分析 行情分析师、新闻分析师和 Memory Log 可以同时工作。此例未选择情绪和基本面分析师。
  4. 汇合 父图收齐本轮报告与 Memory 输出，启动多空辩论。
  5. 综合决策 Research Manager 汇总，Trader 提出方案，三种风险角色轮转，Portfolio Manager 输出评级与理由。
  6. 结果 返回最终状态和评级，并写决策日志。需要 Markdown 或 HTML 报告时再调用 save_reports。

一次研究的调用时序

跟着一条工具调用走

  1. market_analyst.py 声明 TOOLS 并构造行情节点。第一次执行时，节点从 AgentState 取标的和研究日期，准备提示词。
  2. turn.py 的 take_turn 把工具定义绑定给模型。模型可直接给报告，也可请求 get_stock_data 等工具。
  3. setup.py 的 _tools_or_done 检查返回消息中的 tool_calls。如果有调用，ToolNode 用相同的工具集合执行请求。
  4. tools.py 中的 get_stock_data 约束请求日期并调用 route_to_vendor。路由根据工具或类别配置选数据供应商。
  5. 工具结果进入同一分析师的消息历史。模型可再次请求工具或写报告。达到轮次上限时，子图要求模型总结并结束。

可按 市场分析师 → 模型调用 → 子图和条件边 → 工具 → 供应商路由 的顺序对照源码。

Phase 1 · 原版源码分析

审计基准为本地 develop 的 9fa1196fffbcfd9de5146d2dd2869df84ab99838，与本地 origin/main 相同。origin 指向 liushuai37/TradingAgents-Ashares，upstream 指向 TauricResearch/TradingAgents。本地无 upstream/main 引用，未独立比对远端 HEAD。任务开始时 AGENTS.md 与交接文档已暂存，.idea/ 未跟踪。许可证见 LICENSE（Apache 2.0）。

README 提供 pip、Docker、CLI 和 Python API 启动说明。pyproject.toml 要求 Python ≥3.11，声明 LangGraph、SQLite checkpoint、LangChain 模型客户端、pandas、yfinance、Typer 等依赖。dev extra 提供 pytest，默认排除 integration，CI 在 Linux 测试 Python 3.11–3.14。以下链接和符号均以该 commit 为准。

执行链路

  1. 入口。pyproject 的 tradingagents = cli.main:app 指向 cli/main.py 的 Typer 应用。其 analyze 进入 cli/run.py 的 run_analysis，由 _build_run_config 合并输入并构造 Graph，随后创建 State、配置回调和 checkpoint、迭代 stream_run、记录决策和选择导出。程序入口是 trading_graph.py 的 TradingAgentsGraph.propagate(ticker, trade_date, asset_type, portfolio)，日期需为非未来的 YYYY-MM-DD。它在 run config 和 checkpoint 作用域中执行 _run_graph，通常同步 invoke，debug 则消费流，最终给出 (final_state, rating)。
  2. 组装。TradingAgentsGraph.__init__ 创建 quick/deep 客户端、Memory Log 和 ConditionalLogic，调用 setup.py 的 GraphSetup.setup_graph 后编译。create_run_state 调用 propagation.py 的 Propagator.create_initial_state，注入证券身份与可选持仓。身份查询走 context.py 的 resolve_instrument_identity，独立于工具供应商路由。
  3. 并行取证。setup_graph 从 START 扇出到选中的分析师和 Memory Log，add_edge(first_steps, "Bull Researcher") 等待全部结束。analyst_execution.py 的 ANALYST_NODE_SPECS 将四种键映射到节点、报告字段及工具。四者都用 _analyst_graph，各自保有消息历史，只向父图返回各自的报告字段。
  4. 工具循环。market、news、fundamentals 在 turn.py 的 take_turn 调用绑定相同 TOOLS 的模型。_tools_or_done 检查最后的 tool_calls，进入 ToolNode 或结束。每条带调用的模型消息计为一轮，可含多个调用。默认 20 轮，到限转 wrap_up，把工具交互转成文本并用未绑定工具的模型汇总，随后直接结束。默认递归上限 100，构造时验证其大于 2 * max_tool_rounds + 2。social 无 ToolNode，sentiment_analyst.py 的 create_sentiment_analyst 先直接取新闻、StockTwits 和 Reddit，再调用模型。
  5. 综合研判。conditional_logic.py 按 count 和说话者路由。Bull → Bear 交替，达到 2 × max_debate_rounds 后进入 Research Manager → Trader。Aggressive → Conservative → Neutral 串行轮转，达到 3 × max_risk_discuss_rounds 后由 Portfolio Manager 结束。两个轮数默认为 1。辩手调用普通模型并更新辩论状态，两位 Manager 使用 deep，其余用 quick。Trader 与两位 Manager 通过 structured.py 尝试结构化输出并保留文本回退，均无 ToolNode 循环。
  6. 落盘与输出。record_decision 写每标的/日期上的 JSON 状态文件并记待结算决策。同标的同日的文件路径可覆盖。成功才清除相应 checkpoint。rating.py 的 run_rating 处理五档评级与不可解析时的 REVIEW。save_reports 是独立导出入口，reporting.py 的 write_report_tree 和 report_html.py 生成分节 Markdown、可选 HTML。

本地运行验证

Windows 隔离环境使用 CPython 3.12.14，安装项目及 dev extra 成功，主要解析版本为 TradingAgents 0.7.1、LangGraph 1.2.24、langchain-core 1.8.4、checkpoint SQLite 3.1.3 和 pytest 9.2.0。默认网络权限下访问 PyPI 返回 socket 10013，经允许联网后完成安装。未修改项目依赖声明。

  • python -m pytest -q tests/test_graph_end_to_end.py，15 项通过。该套件通过 ScriptedModel 和 offline fixture 隔离模型与供应商，实际调用 TradingAgentsGraph.propagate 和流式路径，覆盖完整决策与落盘、结构化及文本回退、分析师并行、增量报告、工具轮次上限、checkpoint 恢复、Memory 结算和配置隔离。
  • tradingagents --help 成功显示已安装入口及命令。
  • python -m pytest -q 沙箱运行结果为 1406 通过、1 失败、6 跳过、1 取消选中，另有 100 项子测试通过。跳过项来自 Windows 与 POSIX 环境差异及可选 Bedrock SDK 缺失，默认筛除 integration。唯一失败为 tests/test_chatgpt_auth.py::test_the_browser_answer_reaches_the_loopback_and_strays_are_ignored，沙箱访问 127.0.0.1 被拒（WinError 10013），继而超时。允许本地回环后单独重跑该用例通过。
  • 本次未配置可验证的真实模型和数据连接。测试价格、报告和模型响应来自 fixture，A 股行情、供应商 usage 和服务端 SSE 接入仍待验证。

Phase 1 · 扩展点与边界

源码基准 9fa1196fffbcfd9de5146d2dd2869df84ab99838。运行验证见原版源码分析。

切面 现有实现与定位 现有接口的接入边界
模型 factory.py create_llm_client/create_tier_client/build_llm_kwargs 区分原生 Anthropic、Google、Azure、Bedrock 及 openai_client.py 中兼容供应商；quick/deep 可分别设置模型、供应商及端点。默认和环境变量见 default_config.py 原版接受环境变量、运行配置和分档模型参数。具体可用参数取决于供应商客户端。
工具 tools.py 的模块级工具，analyst_execution.py 的静态 specs，setup.py 的 ToolNode 与各分析师 TOOLS 新增模型可调用工具时，需同时核对模型绑定与 ToolNode 的工具集合。
数据路由 router.py 的 TOOLS_CATEGORIES、VENDOR_METHODS、get_vendor/route_to_vendor。工具级覆盖分类，显式有序链过滤不支持方法的供应商，default 使用该方法全部可用供应商。区分无数据、供应商不可用和可传播异常；宏观/预测市场可降级 身份查询、情绪预取部分来源及 Memory 结算各有独立路径。修改工具供应商映射只影响经过该路由的调用。
配置隔离 config.py 的 run_config/run_config_context 使用 ContextVar，get_config 优先读取运行配置；Graph 构造时仍调用进程级 set_config，Graph 字段含可变 checkpoint 状态 工具在运行作用域内读取配置。构造阶段仍影响进程级配置，checkpoint 也保存在 Graph 实例上。
监控 trading_graph.py stream_run 消费带子图的 values/tasks，外部只接到消息和状态片段；顶层 task start/end/errors 未透传。propagation.py get_graph_args 可注入回调；stats_handler.py 统计模型/工具开始及响应 usage。CLI 还有据报告推断的状态 模型回调和工具回调分别接入。情绪节点直接调用供应商的部分不会自动产生 ToolNode 事件。
异常、取消、恢复 Graph 通过同步 invoke/stream；流在 finally 关闭。运行异常可传给调用者，工具错误与供应商降级另有语义，Memory 错误可保留研究。checkpoint 生命周期由 Graph 管理 源码提供 SQLite 节点续跑。研究任务级取消、重试记录和服务恢复没有公共入口。

按 tradingagents/、cli/ 中的定义和调用点审计，create_*_analyst 等角色工厂和 GraphSetup.setup_graph 已存在，动态 Agent Factory/Registry、Workflow Registry、Skill Loader、MCP Client、通用 Hook Manager 未见对外入口。模型供应商工厂、LangChain callbacks、工具静态映射提供明确的复用基础。
